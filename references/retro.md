# 执行后复盘（Retro）

> 知止的"自改进"机制：每次执行后一行复盘，跨使用积累经验，让 skill 越来越准。

## 为什么需要复盘

没有复盘，skill 每次执行都是孤立的——漏过的缺口、错的假设会反复犯。一行复盘把"这次教训"沉淀下来，下次触发时自动想起。

## 复盘格式（一行三问）

```
[retro] 漏掉的缺口：{类别：描述，或"无"}
[retro] 错误的假设：{假设：实际发现，或"无"}
[retro] 下次改进：{一句话}
```

## 复盘时机

- T1 / T2 任务**完成后**立即输出（T0 不需要）。
- 复盘输出在最终回复末尾，不打断执行流程。

## 复盘示例

```
[retro] 漏掉的缺口：A-版本：没先查项目用的 Node 版本，默认用了 20 的特性
[retro] 错误的假设：假设依赖已装，实际需要先 Glob 检查 package.json
[retro] 下次改进：涉及运行时/依赖时，先 Glob 配置文件再动手
```

## 记录与累积（可选）

- 复盘随对话输出即完成作用。
- 可选：追加到本地记录 `~/.zhizhi/retro.md`（尊重用户目录偏好，**不自动写入**，需用户确认后启用）。
- 累积到一定量后可回看：哪类缺口最常漏、哪个假设模式最常错——据此调整 SKILL.md 的触发词与检查项。

## 与饕餮（skill 进化）的关系

复盘产出的是"使用层面"的改进信号；若发现是**方法论层面**的缺陷（如某类缺口总是漏检），把信号交给 skill 进化流程（如 taotie）做结构性改进。
