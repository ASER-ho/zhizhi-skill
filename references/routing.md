# 自适应路由、委托与检索预算

> SKILL.md Step 2 的详细参考。核心：**不重复造检索轮子**——项目内 Glob/Grep，代码类定向查，调研类委托可用调研 skill（探测式，不硬绑）。

## 路由决策树

```
Step 1 识别出缺口
│
├─ 缺口在项目内？（已有代码/配置/依赖）
│   └─ YES → Glob/Grep 本地搜索（P0，不联网）
│
├─ 缺口是代码/API/错误信息？
│   ├─ API签名/参数/版本 → WebSearch + WebFetch 官方文档（P1）
│   ├─ 错误信息排查 → WebSearch 搜错误，优先 SO/GitHub Issues（P2）
│   └─ 成熟库发现 → WebSearch GitHub + WebFetch README（P2）
│
├─ 缺口是行业数据/市场/政策/方案对比/学术文献？
│   └─ YES → 委托可用的调研 skill（见自适应委托）
│
└─ 以上都不是 → WebSearch 通用搜索
```

## 自适应委托（探测式）

**不硬绑 domain-research**。按优先级探测可用的调研能力：

1. **domain-research**（若可用）→ 委托
2. **用户环境已装的调研类 skill**（如 `research`）→ 委托
3. **都没有** → 降级为 WebSearch 2-3 组关键词多轮交叉，标注"未做多平台交叉验证"

**委托方式**：把 Step 1 缺口清单转化为委托输入（主题 / 目的 / 深度 / 时间限定 / 必须覆盖的缺口）。委托后只补查缺失的缺口，不重复委托。

**注意**：只委托一次。若发现用户在"已有调研 skill 却自己多平台搜"，那是反模式，立即纠正。

## 检索预算（防烧上下文）

| 项 | T1 | T2 |
|----|----|----|
| 每缺口检索轮数 | ≤2 | ≤3 |
| 每缺口 WebFetch 页数 | ≤1 | ≤2 |
| 关键词调整上限 | 3 轮 | 3 轮 |

**关键词三轮法**：第1轮主体+功能（"pandas read_csv skip rows"）→ 第2轮加版本（"pandas 2.x read_csv"）→ 第3轮换同义词/英文（"pandas skip rows before header"）。3 轮无果 → **标记"未找到"，停止续搜**。

**超预算处理**：宁可承认查不到（进 Step 4 标注假设），不烧上下文。

**检索范围约束**：只查与当前任务直接相关的缺口，不借题发挥扩展检索范围（修 bug 不顺便调研无关选型）。检索服务于任务，不服务好奇心。

## 检索要点

- **P1 官方文档**：用 `allowed_domains` 限定官方域名（不用 `site:` 语法）；WebFetch `prompt` 精确指定提取目标，不抓整页。
- **P2 GitHub/SO**：GitHub 优先高 star、最近更新；SO 优先高票但注意回答时间。检查许可证与版本。
- **降级策略**：调研 skill 不可用 → WebSearch 交叉；WebFetch 超时/503 → 退避重试（1s→2s，最多2次）；404/403 → 不重试换源；官方文档站不通 → GitHub README / SO。
- **重试原则**：瞬时错误（超时/503）退避重试 ≤2 次；永久错误（404/403）不重试直接换源。**检索失败绝不编造**。

## 来源可信度（多轴判定，不单看 star）

star 多 ≠ 正确 / 在维护 / 版本匹配 / 安全。综合 5 轴判定：

| 轴 | 高 | 低 |
|----|----|----|
| ① 来源权威性 | 官方文档 / 厂商 | 个人博客 / 匿名 |
| ② 新鲜度 | 有明确日期且近期 | 无日期 / 多年未更新 |
| ③ 版本匹配度 | 与项目版本一致 | 面向不同版本 |
| ④ 维护状态 | 持续提交 / issue 响应 | 停滞（哪怕 star 多） |
| ⑤ 直接证据强度 | 一手（源码/官方文档） | 二手转述 |

**任一轴为关键负面即降级**：版本过时、官方已废弃、无维护（哪怕 50k star）→ 降级甚至弃用。D 级（AI 生成/未知来源）不采用或仅参考。

## 去重与摘要

- URL 去重、内容去重（保留信息更完整的）、转载保留原始来源。
- 每个结果提取结构化摘要：来源 / 标题 / 发布时间 / 核心内容 / 关键数据 / 适用版本 / 可信度。
