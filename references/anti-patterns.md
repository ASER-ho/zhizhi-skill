# 反模式（Anti-Patterns）

> "知止"的反面是"埋头硬推、不检索、硬编造"的封闭执行模式。本文件列出每个反模式的识别信号与纠正方法。

## 1. 无检索先编码
- **识别**：任务涉代码但未做任何 WebSearch / Glob / Grep；直接写 import / 函数定义。
- **纠正**：先 Grep 项目内已有实现 → WebSearch 成熟库 → 评估复用 → 确实没有才自己写。

## 2. 编造事实
- **识别**：用"应该是/大概/通常/一般来说"填版本号、API 签名、参数行为；引用不存在的函数。
- **纠正**：WebFetch 官方文档核实；给不出依据就明确说"未确认"，不填。

## 3. 封闭推理
- **识别**：连续 2 轮以上同一问题反复推理，大量"可能是因为/也许是"，无外部新信息。
- **纠正**：停止推理，搜错误信息/文档，用证据定位。

## 4. 无视文档
- **识别**：用户给了链接/文件却不 WebFetch / Read，凭记忆回答。
- **纠正**：先读用户提供的资料，再回答。

## 5. 盲目复用
- **识别**：搜到代码直接粘贴，不查版本兼容、依赖是否已装、许可证、编码规范。
- **纠正**：Glob 依赖文件 → 查版本 → 查许可 → 适配规范后再用。

## 6. 重复检索
- **识别**：有可用的调研 skill（domain-research / research）却自己多平台搜；重复实现检索轮子。
- **纠正**：调研类委托，本 skill 只定义缺口和校验结果；代码类才直接定向查。

## 7. 海量灌入
- **识别**：把整页网页塞进上下文，不加筛选。
- **纠正**：WebFetch `prompt` 精确指定提取目标；分多次提取；只保留与当前缺口相关的摘要。

## 8. 隐藏假设
- **识别**：输出无"假设"部分；把未确认信息当事实；不标注结论依据。
- **纠正**：信息不足用 AskUserQuestion；无法确认则显式列假设（含影响与确认方式）。

## 9.（新增）流程失配
- **识别**：轻任务（T0/T1）被拖进完整流程，或重任务（T2）被当轻任务草草跳过。
- **纠正**：先分级再决定流程深度；拿不准升一级；流程是手段不是目的。

## 10.（新增）盲目附和
- **识别**：用户断言与证据/事实矛盾时，不验证就直接接受；用户说"应该是 X"就跟着说"对，是 X"。
- **纠正**：证据与用户断言冲突时，**带证据反驳**（尊重但坚持独立判断）；无法验证时说"未核实"，不附和。

## 11.（新增）检索越界
- **识别**：检索内容与当前任务无关（修 bug 却调研无关选型）；检索范围随兴趣蔓延。
- **纠正**：只查与任务直接相关的缺口；检索服务于任务，不服务好奇心。

## 自检清单（执行前快速过）

- [ ] 我是否无检索就写代码/方案？
- [ ] 我是否用"应该是/大概"填充关键事实？
- [ ] 我是否连续 2 轮以上空转推理？
- [ ] 用户给的链接/文件我读了吗？
- [ ] 引用代码是否查过版本和许可？
- [ ] 调研类是否委托了可用调研 skill（没自己多平台搜）？
- [ ] 多方案是否做了评分/快速判断？
- [ ] 是否把搜索结果整页塞进上下文？
- [ ] 输出是否显式列出未验证假设？
- [ ] 是否检查过项目内可复用代码？
- [ ] 流程深度是否与任务等级匹配？
